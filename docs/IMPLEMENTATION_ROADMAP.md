## 代码批次与通过条件

### 0 正式共享状态与协议

在Core补齐单位、报文、资源、台站、移动/动作状态和命令结果类型。在fixtures/protocol增加正式Observation、Command、Snapshot、Result。权威坐标、ID、耗时、冷却和半分使用整数，正式协议使用独立版本标识，保留现有Bootstrap数据读取。

通过条件为共享样例可解析、校验，首条重复命令与下一tick生效规则可验证，旧Bootstrap回归继续通过。

同时在Ubuntu预检沙箱执行器权限、CPU计量和256 MiB限制，尽早发现基础设施阻塞。原Unity基线导入故障继续作为发布门槛跟踪，日常验证沿用获准的独立副本。

### 1 固定地图与真实移动

新增fixtures/world/map-v1.json，落实96×96旋转对称、出生点、双方报点与兵站、中央区域、桥渡口和架桥点，记录地图摘要。

World新增MapLoader.cs、MovementSystem.cs、CrossingQueue.cs，复用GridPathfinder.cs。实现目标格预留、整数边计时、到达事件、冲突轮换、10 tick阻挡重寻路、桥渡队列及运输员双倍耗时。Integration新增RelayMatchEngine.cs组合调用，Presentation接实际位置快照。

通过条件为单位能按命令抵达报点，不能穿河越界，交换阵营后对应场景耗时一致，同命令重演的逐tick位置和队列顺序一致。

### 2 平报得分

Rules新增MessageSystem.cs和ScoreLedger.cs。先完成平报刷新、任务ID、容量、拾取、转交、交指挥所和重复交付拒绝。账本记录tick、任务、原始分、倍率及整数半分。Integration按R15调用各系统，通过ObserverSnapshotBuilder.cs输出真实观战数据。

通过条件为脚本命令控制单位取得平报并送达得分，600/601 tick、超期900/901 tick边界正确，同一任务不重复计分。该批尚需C++接入才能通过M1。

### 3 C++ SDK与两支AI

新增sdk/cpp，固定JSON依赖与许可。封装getframeinfo、moveTo、loadMsg、deliverMsg、wait，随后补齐全部指令。两支样例AI均只读取公开Observation。

Integration/Ai/AiProcessBridge.cs管理每方独立进程、受控stdin/stdout、帧长、tick/版本、动作数、stderr截断、取消及清理。先使用自有可信样例测试协议。新增tools/check-local-match.ps1，组合样例编译、对战与产物校验。

通过条件为两支C++ AI实际移动、送报得分，同场回放能被Windows客户端打开。保留AI源码摘要、种子、有效动作、账本和重演摘要，崩溃、无输出及畸形输出可控。至此宣布M1通过。

### 4 完整规则与权威视野

依次实现以下系统。

1. VisibilitySystem及按阵营Observation，防止全图、隐藏单位和资源泄露。
2. RadioNetwork、架台撤台、节点连通、沿链路送报。
3. MaterialSystem、ConstructionSystem，库存、预留/退回、桥与中继。
4. 急报、密报译电、通播、总攻令，含双方资格、同tick交付和连续进度。
5. 压制、冷却、天气恢复、补偿及公共种子事件表。
6. 枢纽三条件、器材结余、双局换边、胜负、平局与整场判罚。

通过条件为R01—R18各有边界用例，附录668分分账通过，完整9000 tick及双局聚合通过，Windows/Linux固定输入状态摘要一致。4号同步显示正式背包、任务、施工、队列和账本。

### 5 隔离编译与正式Worker

在server/Worker新增SandboxCompiler.cs、SandboxAiRunner.cs，复用现有可信裁判调度的取消、产物校验和回收行为。deploy/sandbox锁定执行器、只读运行环境、命名空间、系统调用和各项配额。编译与运行AI均使用低权限隔离身份。

通过条件为Ubuntu合法AI正常完成，联网、读取宿主文件、线程/子进程、死循环、内存增长、输出洪泛、编译超时和取消均有真实限制及清理证据。10ms CPU、100ms墙钟及256 MiB限制可验证。通过后再开放第三方提交评测。

### 6 账号、提交、任务与真实页面

扩展server/Platform，使用ASP.NET Core Identity、EF Core SQLite，建立队伍、提交、编译产物、任务、结果与产物索引。实现身份与归属检查、裁判发起比赛、持久化状态和重试/重启恢复，替换DemoPageModel静态数据。提供授权观战快照、日志和回放下载。

通过条件为网页上传ai.cpp后，隔离编译、双局评测、真实结果与回放可查。越权请求被拒绝，重复请求不产生重复结果，服务重启不静默丢任务。

### 7 发布与Ubuntu全流程验收

扩展现有打包与Ubuntu工具，加入正式玩法、SDK、隔离与数据库检查。输出Windows观战包、Linux裁判、平台/Worker、SDK与样例、规则手册和部署指南，附版本与摘要。

通过条件为干净Ubuntu部署后完成上传到结果全流程，完整长局、并发与异常回归通过，数据库备份恢复、磁盘清理、更新和回滚实际可执行。原Unity版本兼容性需有实际导入/构建结果，仍有阻塞时明确记录。

## 单人执行顺序

依次推进批次0—3完成最小闭环，再做4—7。批次0的基础设施预检可利用构建等待时间推进。每批完成实现、回归、进度更新和可审查提交。

首个代码批次限定为正式状态、地图配置及移动推进。当前无需再等待其他同学提供模块，后续进度证据写入[单人开发进度](SOLO_PROGRESS.md)。
