# 架构与职责

## 一条比赛数据链

选手提交 ai.cpp → 平台登记并保存源码哈希 → 隔离编译 → worker 启动两局独立裁判 → 每局分别启动红蓝 AI 沙箱 → 裁判发各方可见帧 → SDK 提交动作 → 下一 tick 生效 → 裁判输出快照、事件和得分账本 → 平台保存产物 → Unity 观战/回放显示。

两局仅共享冻结的输入参数与随机种子，不共享运行时状态、AI 存储、通信通道或网络。正式主机在 Ubuntu 运行，Windows 客户端不是权威判分端。

## 模块归属

| 模块 | 负责人 | 输入 | 输出 | 不能承担的职责 |
| --- | --- | --- | --- | --- |
| Core | 1 | 配置、基础数据 | 共享状态/命令/事件类型、确定性工具 | 不依赖画面、物理帧率或World/Rules程序集 |
| Engine组合入口（Integration） | 1 | 初态、已校验动作、tick | 调用World/Rules后的权威状态、快照和哈希 | 不复制移动和计分逻辑 |
| World | 2 | 地图配置、移动请求、占用 | 路径、移动状态、可见集合 | 不计算报文/终局分数 |
| Rules | 3 | 状态、动作、移动结果 | 链路、任务、资源及分账 | 不在 UI 中维护第二套计分 |
| Presentation | 4 | 只读快照、事件、回放 | 地图、迷雾、UI、镜头 | 不提交单位控制指令 |
| AI bridge / SDK | 5 | 过滤后的帧 | 校验后的候选动作、执行诊断 | 不获取全图隐藏状态 |
| Headless adapter | 1 | 比赛清单、AI bridge | 裁判进程结果、产物 | 不直接执行不可信源码 |
| Platform / worker | 5 | 源码、赛程请求 | 排队状态、比赛结果、产物入口 | 不覆盖 Core 判分；不以 Web 服务权限运行 AI |

## 时间、确定性与回放

- 规则以固定 tick 推进；Unity Update 只负责显示与驱动，不把渲染 deltaTime 当游戏时间。
- 核心采用整数 tick、整数资源和可精确表示的坐标/计分。固定点精度、移动余数、距离度量必须在 M0 契约中锁定。
- PRNG 算法与版本固定；随机状态属于比赛状态。相同种子、配置和有效动作序列应产生相同哈希。
- 路径同价、同时拾取、队列同刻进入等必须有稳定且对换边公平的裁决方式，不能依赖字典迭代或机器速度。
- Core、World、Rules 使用 Unity 可用的 C# 子集，禁用 UnityEngine 类型、系统时钟和未注入的随机源；通过 asmdef 明确依赖。
- 回放记录权威动作、事件及检查点；快照可用于观看，动作重演用于审计，两者都保留。
- 3 号定义得分事件并从权威状态生成回放内容；1 号负责文件写入与 headless 出口；4 号只负责加载展示。
- 暂停/倍速只影响播放或墙钟执行速度，不改变 tick 规则；正式 AI CPU 预算不随倍速变化。

## 服务部署边界

- API、数据库和产物目录与不可信编译/运行任务分离；worker 使用独立权限。
- 单机第一版使用持久化任务状态和有界并发，不引入分布式队列/Kubernetes。并发上限由 Ubuntu 实测确定。
- SDK 通过受控 stdin/stdout 传输协议；调试内容走受限 stderr。允许的协议管道不表示允许文件、任意网络或其他 IPC。
- 编译过程同样可能处理恶意源码，必须隔离并限制时间、内存、输出和磁盘。
- 沙箱必须限制网络、文件可见范围、进程/线程创建、CPU、内存、输出、临时盘及生命周期。基础容器不是完整赛事隔离方案；5 号提供可验证的权限和系统调用策略。
- 运行时禁用文件访问的具体允许系统调用集合，必须考虑动态加载和标准库启动需要；由 5 号验证执行模型，不简单声称拦截 open 即完成。
- 不把正式 10ms 预算等同“含网络/进程启动的一次 HTTP 请求用时”；计时口径在规则冻结时确定。
- 日志/回放含全图信息，只向授权观众和裁判发布；AI 帧接口永远过滤迷雾。提交结果、源码和比赛管理必须验证身份与归属。

## 协调方式

1 号负责日常集成和跨模块接口，3 号负责规则问题整理；用户/规则负责人决定赛事语义。技术实现选择在 Issue 中记录并由相邻负责人审查。未定规则不阻止做与其无关的最小演示，但阻止宣称正式规则完整。

具体使用的工具、文件级归属和1/5号worker分担方式见[技术栈与联调手册](IMPLEMENTATION_GUIDE.md)。Web页面采用Razor Pages：4号负责.cshtml/CSS布局，5号负责PageModel、登录/权限和数据库；Web服务不直接执行比赛，独立.NET worker调用1号的MatchRunner与5号的沙箱适配器。
