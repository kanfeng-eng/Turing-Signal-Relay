# 2号：地图、寻路、移动与可见性

先读[总README](../../../README.md)、[契约](../../CONTRACTS.md)、[规则台账](../../RULES.md)。Unity工程由1号建立，不自行生成第二个工程。

## 你负责什么

- 96×96对称地图、地形代价、关键点与可达性验证。
- A*、移动耗时、格占用、碰撞处理、渡口/桥单人队列。
- 各单位视野与阵营可见集合；与5号联合防止迷雾信息泄露。
- 原文未明确的距离/方向/碰撞规则形成R03/R04/R09/R16/R17建议，交3号汇总。

主目录：`game/Assets/Game/World/`、`Tests/World/`、`fixtures/world/`。地图配置结构由你提出、1号审查；不编辑Bootstrap或观战Prefab。

## 第一批工作

1. 无工程时先提交一个地图数据草案与路径fixture：固定起点终点、阻挡、期望代价和路径；M0确定坐标/方向后再锁结果。
2. 1号工程合入后，从main创建`feat/2-grid-pathfinding`，实现小地图的可达/不可达A*，明确同价路径稳定排序。
3. 扩展到96×96，对关键点做180°对称性与合法运输连通检查；先固定测试图再实现种子生成。
4. 接入单位移动和地形耗时；用整数tick累计，避免渲染帧率改变结果。
5. 按定稿规则实现桥/渡口队列和视野；让1、3、5号使用同一组数据。

## 接口交付

提供给1号：地图输入、路径查询、逐tick移动结果、合法/不可达原因、按side可见集合。

提供给3号：到达事件、地形/建造点查询、站点/单位距离计算；3号确认桥建成后你更新通行性，不由你扣器材或加分。

提供给4号：地形与静态点快照、单位位置、迷雾遮罩数据；画面表现由4号做。

提供给5号：已过滤的Observation构造数据；静态地图是否全知按R16决定，不把完整状态透传。

## 验证与验收

- 对称映射两次回原坐标；相同种子输出完全相同地图；所有指定起终点满足最终可达约束。
- 无路时及时返回失败，不死循环；路径不穿河或越界；道路/草地/山地累计耗时符合定稿公式。
- 多单位同刻排队、迎面冲突、渡口关闭、运输员双倍耗时有fixture；避免固定红方优先造成偏差。
- 敌人在边缘进出视野，Observation随之变化；隐藏敌方不能通过坐标数组或错误信息泄露。
- M1交付“AI发moveTo → 单位按路径到达”的日志和可视化位置数据；M2在完整9000tick中无堵死程序。

暂时不用3D NavMesh或Unity物理充当权威格网规则；不用随机打乱来掩盖同价路径和碰撞语义。
