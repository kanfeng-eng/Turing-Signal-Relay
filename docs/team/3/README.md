- 668分例子逐项通过，37.5等半分不丢精度；到期、超期30秒和终局端点均有测试。

规则变动时同步配置版本、台账、fixture和SDK说明；不要仅修改某个C#常量。

## 技术栈：用C#实现可审计规则

| 技术 | 用来完成什么 | 你的交付物 |
| --- | --- | --- |
| C#类、枚举、集合 | 表示报文、资源、技能和任务进度 | Rules中的状态与规则函数 |
| 图搜索BFS/DFS | 求通信节点到指挥所的连通性 | LinkSystem及节点/边/可达集合 |
| 有限状态机+整数tick | 架台、建造、译电、压制、冷却 | 明确进入/退出/中断条件的状态更新 |
| 事件时间表 | 固定时刻刷报、天气、阶段和终局 | PhaseSystem；只读配置驱动 |
| 整数半分与逐项账本 | 精确处理37.5等得分、上限、聚合 | ScoreSystem、ScoreEntry、结果fixture |
| Unity Test Framework/EditMode | 不依赖画面验证玩法 | Tests/Rules回归，含668分样例 |

你不需要机器学习框架。这里的AI是选手写的C++策略，规则系统只是公平执行和计分。图半径、天气效果、时序等按台账定稿，不能由某个搜索算法顺便决定规则。

## 一条规则如何从文字变成代码

以“架台2秒”为例：

1. 先核对开始条件、是否允许移动中发起、是否能取消等未定项R06。
2. 将定稿条件写进状态转换表：未架台 → 架设中 → 已架台；以10tick/s换算2秒为20tick。
3. 为开始tick、完成前一tick、完成tick及取消写输入/期望状态，边界包含由R15裁定。
4. 状态完成时更新通信节点并发事件；4号只显示进度，不开另一个2秒判定器。
5. 1号把事件记入回放；重演同输入应在同tick产生同事件。

四类报文也按同样办法逐个实现：刷新 → 可获得 → 携带/译电/覆盖 → 交付或过期 → 单次记账。共享急报机制R01未定前不自行实现复制逻辑。
