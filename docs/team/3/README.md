# 3号：通信、任务、建设与计分

先读[总README](../../../README.md)、[契约](../../CONTRACTS.md)、[规则台账](../../RULES.md)。你是规则台账维护人，用户/规则负责人是最终裁定人。

## 你负责什么

- 架台/撤台、固定中继、链路与压制、天气影响。
- 四类报文和总攻令、译电、运输/交付、资源刷新、建设消耗与得分。
- 阶段事件、落后补偿、枢纽终局、结余、双局分账与胜负判定。
- 逐项得分事件、完整结果、回放所需规则数据；帮助5号接入结果展示，不承担沙箱。

主目录：`game/Assets/Game/Rules/`、`Tests/Rules/`、`fixtures/rules/`。你维护RULES和规则配置；配置加载与版本入口由1号接入。

## 第一批工作

1. 无需等待工程：把附录C的668分例子拆成逐项输入与期望账本。
2. 整理R01/R05/R06等影响最小闭环的事项，每项给场景例子、可选解释及建议，请用户集中定稿。
3. 工程合入后创建`feat/3-message-score`，先实现一份平报经合法交付产生分数的纯C#路径。
4. 接入链路和资源，再逐步实现其余报文、建设与天气；每个机制留最小边界回归，不一次塞进一个大脚本。
5. 给1、4、5号交付统一ScoreEntry/事件/结果字段及一个固定得分fixture。

## 模块边界

- 2号决定移动、占用与可见集合；你读取到达/位置数据，不重新寻路。
- 你决定桥能否建成、扣器材及得分，通知2号更新通行性。
- 1号决定tick生命周期与文件输出；你生成权威规则事件和结果，不在Update中另开计时器。
- 4号显示你的分账和链路，不能自行推算正式分数。
- 5号采集AI指令，规则合法性仍由你的能力检查与1号命令管线共同完成。

## 验证与验收

- 668分例子逐项通过，37.5等半分不丢精度；到期、超期30秒和终局端点均有测试。
- 重复交付不重复计分，资源不凭空增加；建造上限是得分上限还是数量上限，按定稿验证。
- 架台2秒、压制4秒/CD25秒、译电5秒、通播持续3秒在固定tick下可验证。
- 天气开始/结束、断链恢复、终局三项各40分分别成立时不会误计其他项。
- 两局总分、单局最高分、急报数按顺序比较；再次平分及异常局处理必须等待R12裁定。
- 同输入重复执行，账本和哈希一致；OPEN项未清零不标“完整正式规则”。

规则变动时同步配置版本、台账、fixture和SDK说明；不要仅修改某个C#常量。
