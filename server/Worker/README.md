# Bootstrap裁判进程调度

使用.NET10构建，输入可信Unity裁判的绝对路径、新的产物目录和超时秒数。每局使用独立目录与进程，两局按顺序运行。

```powershell
dotnet run --project server/Worker/Worker.csproj -- <裁判可执行文件> <新的产物目录> 30
```

每局生成回放、结果和日志，总目录写runs.json。成功需要进程退出0、结果版本与状态有效、最终状态哈希匹配及回放文件摘要一致。共享配置和状态哈希源码直接引用Unity Core文件。

超时会终止整个子进程树并等待退出。外部取消同样回收进程后传播取消。输出目录已存在时拒绝覆盖。失败、缺少产物和超时均写入可诊断结果，总体退出1。

已在Windows和Ubuntu实测两局9000 tick、退出7、退出0但缺产物、以及1秒超时。Ubuntu另验证两个调度器争用同一目录时仅一方成功，产物保持完整。两次独立正常运行状态哈希一致。共享Unity DTO启用.NET nullable分析时有两条CS8618警告，当前构建成功。

该入口供基础进程联调。正式MatchJob、AI沙箱入口、双局换边映射与结果落库等待5号契约，正式规则组合等待2/3号实现。
